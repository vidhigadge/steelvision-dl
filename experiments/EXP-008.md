# EXP-008 — Bounding Box Coordinate Mapping to Original Image Space

## Objective

Map defect bounding boxes predicted on resized or processed images back to the coordinate system of the original image.

This is required because later SteelVision-DL stages may perform detection on resized or super-resolved images while defect locations still need to correspond to the original input image.

---

## Mapping Principle

For a processed image with size:

```text
processed_width × processed_height
```

and an original image with size:

```text
original_width × original_height
```

the scale factors are:

```text
scale_x = original_width / processed_width
scale_y = original_height / processed_height
```

A bounding box represented as:

```text
(x1, y1, x2, y2)
```

is mapped using:

```text
x_original = x_processed × scale_x
y_original = y_processed × scale_y
```

---

## Implementation

The coordinate mapping utility was implemented in:

```text
src/detection/coordinate_mapping.py
```

The function accepts:

```text
bounding box
processed image size
original image size
```

and returns the corresponding bounding box in original-image coordinates.

---

## Basic Validation

A synthetic test used:

```text
processed image size = 800 × 800
original image size = 200 × 200
```

with the processed-space box:

```text
(200, 100, 600, 500)
```

The mapped result was:

```text
(50, 25, 150, 125)
```

which matches the expected 0.25 scaling factor.

---

## YOLO Original-Image Test

The trained YOLO26n detector was first run directly on a validation image.

Image:

```text
scratches_5.jpg
```

Original image size:

```text
200 × 200
```

Prediction:

```text
Class: scratches
Confidence: 0.771

YOLO box:
(136.82, 39.44, 200.0, 195.0)
```

Because the detection coordinates were already expressed in the original image coordinate system, the mapped box remained unchanged.

---

## Resized-Image Mapping Test

The same image was resized from:

```text
200 × 200
```

to:

```text
800 × 800
```

The detector was then run on the resized image.

Prediction:

```text
Class: scratches
Confidence: 0.773
```

Processed-image bounding box:

```text
(551.2, 159.08, 800.0, 784.45)
```

Mapped back to original coordinates:

```text
(137.8, 39.77, 200.0, 196.11)
```

---

## Comparison

Direct original-image prediction:

```text
(136.82, 39.44, 200.0, 195.0)
```

Mapped resized-image prediction:

```text
(137.8, 39.77, 200.0, 196.11)
```

The two boxes are very similar.

The small difference is expected because resizing can slightly alter the detector's predicted bounding-box boundaries.

---

## Main Finding

The coordinate transformation correctly maps detections from a processed image back into the original image coordinate system.

This enables SteelVision-DL to perform detection on higher-resolution or super-resolved inputs while still reporting defect locations relative to the original image.

---

## Assumptions

The current mapping method assumes that preprocessing consists only of geometric scaling.

It does not yet account for:

- cropping
- padding
- letterboxing offsets
- rotation
- perspective transformations

If such operations are introduced later, their offsets or transformations must also be included in the mapping procedure.

---

## Connection to Super-Resolution

This mapping is directly applicable to super-resolution experiments.

For example:

```text
original image
200 × 200
↓
4× super-resolution
800 × 800
↓
YOLO detector
↓
SR-space bounding box
↓
coordinate mapping
↓
original-space defect location
```

Therefore, detections produced on super-resolved images can still be displayed or analyzed relative to the original input image.

---

## Conclusion

Phase 8 successfully implemented and validated bounding-box coordinate mapping.

The mapped result closely matched the detector output obtained directly from the original image, confirming that the scaling transformation is functioning correctly.

This establishes the coordinate system foundation required for later super-resolution detection, visualization, and explainability stages.
