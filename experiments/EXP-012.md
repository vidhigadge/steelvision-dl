# EXP-012 — FastAPI Inference Backend

## Objective

Build a lightweight FastAPI backend for SteelVision-DL that exposes the selected FP32 ONNX ResNet-50 classifier through HTTP endpoints.

The backend is intended to act as the inference layer between the trained deep learning model and the user interface developed in the next phase.

The main goals of this phase were:

- create a FastAPI application
- verify the backend using health and root endpoints
- load the FP32 ONNX classifier
- accept uploaded steel surface images
- preprocess images consistently with the classification pipeline
- perform ONNX inference
- return predicted class and confidence
- calculate predictive entropy
- return the top-3 class probabilities
- validate input file types
- provide structured API responses using Pydantic

---

The backend was implemented using:

```text
FastAPI
```

The development server used:



## Selected Classification Model

The backend uses the fine-tuned ResNet-50 classifier exported to FP32 ONNX.

The model predicts six steel surface defect classes:

```text

inclusion
patches
pitted_surface
rolled_in_scale
scratches
```

The FP32 ONNX model was preferred over the INT8 alternatives because the quantized models produced unacceptable accuracy degradation during Phase 11.

The selected deployment model therefore remains:

```text
FP32 ONNX ResNet-50
```

## Prediction Endpoint

Endpoint:

```text
POST /predict
```

The prediction endpoint accepts a steel surface image using multipart file upload.

Supported image types:

```text
JPEG
PNG
```

The uploaded image is passed through the same preprocessing pipeline used by the trained ResNet-50 classifier.

---

## Image Preprocessing

The backend preprocessing pipeline is:

```text
uploaded image
↓
load using PIL
↓
convert to RGB
↓
convert to grayscale with 3 output channels
↓
resize to 224 × 224
↓
convert to tensor
↓
ImageNet normalization
↓
convert to NumPy float32
↓
ONNX Runtime inference
```

The normalization parameters are:

```text
mean = [0.485, 0.456, 0.406]
std  = [0.229, 0.224, 0.225]
```

Using the same preprocessing pipeline as the evaluation experiments is important because changing preprocessing at deployment time could cause distribution mismatch and reduce model accuracy.

---

## ONNX Model Loading

The ONNX model is loaded once when the FastAPI application starts.

The backend uses:

```text
ONNX Runtime
CPUExecutionProvider
```

The model is not reloaded for every request.

This design reduces unnecessary overhead and makes inference more efficient.

---

## Probability Calculation

The ONNX model produces raw logits.

A numerically stable softmax function is applied to convert logits into class probabilities.

The predicted class is selected using:

```text
argmax(probabilities)
```

The confidence value is the probability assigned to the predicted class.

---

## Predictive Entropy

The backend also calculates predictive entropy.

Entropy is computed as:

```text
H(p) = -Σ p log(p)
```

where:

```text
p = model probability for each class
```

Lower entropy generally indicates that the model probability distribution is concentrated on one or a few classes.

Higher entropy indicates that the probability distribution is more spread out.

Predictive entropy is used here as a model uncertainty indicator.

It should not be interpreted as proof that a prediction is correct or incorrect.

---

## Top-3 Predictions

The backend returns the three classes with the highest model probabilities.

This provides more information than returning only the top prediction.

For example, a future user interface can show:

```text
1. predicted class
2. second most likely class
3. third most likely class
```

This is useful when the model is uncertain or when multiple defect classes receive meaningful probabilities.

---

## Response Schema

The FastAPI backend uses Pydantic response models.

The response schema includes:

```text
TopPrediction
PredictionResponse
```

The prediction response contains:

```text
filename
predicted_class
confidence
entropy
top_3
```

Each top-3 prediction contains:

```text
class_name
probability
```

Using a structured response model improves API documentation and simplifies frontend integration.

## File Validation

The backend includes basic file-type validation.

Accepted MIME types:

```text

```

Unsupported file types return:

```text

```

with an explanatory error message.

Example error:

```json

  "detail": "Only JPEG and PNG images are supported"

```

---

## Invalid Image Handling

The backend also handles cases where a file claims to be an image but cannot be decoded by PIL.

Invalid image files return:

```text
HTTP 400
```

with:

```json
{
  "detail": "Invalid image file"
}
```

This prevents invalid input from reaching the model inference stage.

## Current Deployment Decision

The API currently uses:

```text
FP32 ONNX ResNet-50
```

rather than an INT8 model.

This decision is based on the Phase 11 results:

```text
PyTorch FP32 accuracy = 99.22%
ONNX FP32 accuracy    = 99.22%
ONNX CPU speedup      = 1.58×
```

while the tested INT8 models showed significant accuracy degradation.

The backend therefore prioritizes prediction quality over aggressive model compression.

---

## Limitations

The current FastAPI backend has several limitations.

- Only classification is exposed through the API.
- YOLO defect detection is not yet available through an endpoint.
- Bounding-box coordinate mapping is not exposed through the API.
- Grad-CAM is not generated dynamically by the backend.
- SHAP explanations are not generated dynamically by the backend.
- The ONNX model must already exist locally before server startup.
- The backend currently uses CPU ONNX Runtime inference.
- Authentication is not implemented.
- Request rate limiting is not implemented.
- Production deployment configuration is outside the current phase.
- The backend was tested locally rather than on a cloud server.

These limitations are acceptable for the current project stage because the primary goal is to create a functional inference service for the SteelVision-DL user interface.
