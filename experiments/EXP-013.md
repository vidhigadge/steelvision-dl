# EXP-013 — Streamlit Application Integration

## Objective

Build a complete user-facing Streamlit application for SteelVision and integrate the major deep learning components developed throughout the project into a single interactive dashboard.

The purpose of this phase was to move beyond isolated research scripts and expose the classification, uncertainty, explainability, localization, coordinate mapping, and resolution-analysis pipelines through a practical interface.

The main goals were:

- create a Streamlit frontend
- connect Streamlit to the FastAPI backend
- support steel surface image uploads
- perform defect classification
- display classification confidence
- display predictive entropy
- provide Grad-CAM explainability
- perform YOLO-based defect localization
- map detected bounding boxes back to the uploaded image
- provide controlled resolution experiments
- clearly separate the standard user workflow from research experimentation
- provide backend-health feedback
- improve usability through a polished interface
- preserve scientific limitations and responsible interpretation throughout the dashboard

# Predictive Entropy

## Purpose

Predictive entropy is used as a simple uncertainty indicator.

Entropy is computed from the complete class probability distribution.

The conceptual calculation is:

```text
H(p) = -Σ p log(p)
```

where:

```text
p = predicted probability for each class
```

A probability distribution strongly concentrated on one class generally produces lower entropy.

A more distributed probability output generally produces higher entropy.

---

## UI Interpretation

The interface uses the following UI-level interpretation thresholds:

```text
Entropy < 0.5
→ Low uncertainty

0.5 ≤ Entropy ≤ 1.0
→ Moderate uncertainty

Entropy > 1.0
→ Elevated uncertainty
```

These values are used only to provide a simple interface-level interpretation.

They are not universal scientific thresholds.

# Coordinate Mapping

## Purpose

YOLO performs detection using the processed detector representation.

The resulting processed coordinates must therefore be mapped back to the dimensions of the uploaded image.

The mapping logic reuses the coordinate transformation implemented during Phase 8.

---

## Mapping Formula

For processed dimensions:

```text
processed_width
processed_height
```

and original dimensions:

```text
original_width
original_height
```

the scaling factors are:

```text
scale_x = original_width / processed_width
scale_y = original_height / processed_height
```

For a processed box:

```text
(x1, y1, x2, y2)
```

the mapped coordinates are:

```text
mapped_x1 = x1 × scale_x
mapped_y1 = y1 × scale_y

mapped_x2 = x2 × scale_x
mapped_y2 = y2 × scale_y
```

This converts detector coordinates into the coordinate system of the uploaded image.

# Interpretation of Detector Confidence

The simulated 128 px image produced a higher detector confidence than the original-image path for this example.

This should not be interpreted as:

```text
128 px image is better
```

or:

```text
lower resolution improves localization
```

Detector confidence only measures how strongly the detector responds to the current processed representation.

Changing resolution can alter:

```text
edges
texture
local contrast
feature patterns
```

These changes can cause the detector to behave differently.

Therefore:

```text
higher confidence
≠
better image quality
```

and:

```text
higher confidence
≠
guaranteed better detection
```

# Resolution Experiment Scientific Note

Simulation modes are designed for controlled experimental analysis.

They intentionally adjust the image to the selected experimental resolution before detection in order to evaluate model behavior under changed visual detail.

These modes do not estimate:

```text
camera distance
```

or recover:

```text
guaranteed missing information
```

The simulation is therefore a research tool for studying model behavior.

It is not a reconstruction of physical ground truth.

---

# Image Resizing Interpretation

The processed image is resized to meet detector input requirements.

This increases image dimensions without guaranteeing recovery of missing detail.

Detected bounding boxes are then mapped back to the coordinate space of the uploaded image.

Therefore, a resized detector image should not be interpreted as a truly restored high-resolution observation.

# Super-Resolution Context

SteelVision previously evaluated neural super-resolution during Phase 6.

Real-ESRGAN was compared against standard bicubic reconstruction.

The classification results were:

```text
128 px

83.92%

Real-ESRGAN:
63.53%
```

```text
64 px

Bicubic:
49.80%

Real-ESRGAN:
41.18%
```

```text
32 px

Bicubic:
31.76%

Real-ESRGAN:
31.37%
```

The neural super-resolution pipeline did not improve classification performance.

Therefore, SteelVision does not assume that visually sharper neural super-resolution output improves downstream defect recognition.

The Resolution Experiment instead provides controlled image-resolution analysis.

# Limitations

The current application has several limitations.

- The classification model was trained using a limited research dataset.
- The YOLO detector depends on a locally stored checkpoint.
- The YOLO checkpoint is located under the ignored `runs/` directory.
- Production deployment therefore requires separate model-weight handling.
- Coordinate mapping currently assumes resize-based scaling.
- Arbitrary cropping is not explicitly handled by the coordinate mapping utility.
- Rotation is not explicitly handled.
- Perspective transformation is not explicitly handled.
- Complex geometric preprocessing is not explicitly handled.
- Resolution simulation does not represent actual physical camera distance.
- Resizing does not guarantee recovery of missing visual detail.
- Real-ESRGAN was not integrated as a guaranteed live enhancement method.
- Grad-CAM does not establish causal physical defect evidence.
- Entropy does not guarantee correctness.
- Model confidence does not guarantee defect severity.
- The application was validated locally.
- Authentication is not implemented.
- Rate limiting is not implemented.
- Production cloud deployment is outside the current phase.
- Performance on unseen industrial environments may differ from the research dataset.

Resizing does not guarantee recovery of missing detail.

Higher confidence does not necessarily indicate improved image quality or improved localization.

Grad-CAM reflects model influence rather than physical causality.

Entropy is an uncertainty indicator rather than a guarantee of correctness.

Resolution simulation does not estimate camera distance.

Neural super-resolution is not assumed to restore ground truth or improve downstream recognition.
