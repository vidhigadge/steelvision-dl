# EXP-015 — Robustness, Cross-Model Agreement, and Supported-Domain Validation

## Objective

Improve SteelVision robustness by addressing two important edge cases:

- disagreement between the ResNet-50 classifier and YOLO detector
- unsupported images being forced into one of the six known defect classes

This phase introduces cross-model agreement analysis, clearer model-role handling, supported-domain validation, threshold analysis, FastAPI enforcement, and Streamlit rejection logic.

---

## Background

Before this phase, SteelVision already included:

- ResNet-50 defect classification
- predictive confidence
- predictive entropy
- Grad-CAM explainability
- YOLO defect localization
- coordinate mapping
- FastAPI backend
- Streamlit frontend
- resolution experiments

Two reliability problems remained.

---

## Problem 1 — ResNet and YOLO Could Disagree

SteelVision uses two different models.

ResNet-50 performs:

```text
image-level defect classification
```

YOLO performs:

```text
bounding-box localization and per-region classification
```

Because the models solve different tasks and were trained separately, they may disagree.

Example:

```text
ResNet:
Patches

YOLO:
Pitted Surface
```

The system should not hide this disagreement or force both models to appear consistent.

Therefore, a dedicated cross-model agreement evaluation was performed.

# Model Integration Policy

Based on the agreement analysis, the final model-role policy became:

```text
ResNet-50 = primary image-level classifier
YOLO = supporting localization model
```

ResNet remains the primary image-level model because:

```text
ResNet test accuracy = 99.22%
```

YOLO provides:

- spatial localization
- bounding boxes
- per-region class predictions
- supporting evidence
- secondary detector observations

---

# Localization Interpretation Rules

## Case 1 — YOLO Detects the ResNet Class

If YOLO detects regions matching the ResNet prediction:

```text
Matching YOLO detections
→ Primary Localization Evidence
```

These regions are displayed as spatial evidence supporting the classifier.

---

## Case 2 — YOLO Produces No Detections

If ResNet predicts a defect but YOLO does not produce a bounding box:

```text
ResNet classification remains visible
Localization is reported as unavailable
```

The UI explicitly states that missing localization does not automatically invalidate the classifier result.

---

## Case 3 — YOLO Detects Only Different Classes

If YOLO produces detections but none match the ResNet prediction:

```text
Cross-model inconsistency warning
```

The application preserves the disagreement rather than hiding it.

---

## Case 4 — Multi-Class YOLO Detection

If YOLO detects multiple classes:

```text
matching ResNet detections
→ primary localization evidence

non-matching detections
→ additional detector observations
```

This preserves useful detector information without forcing artificial agreement.

# Part B — Unsupported Input Problem

The ResNet classifier contains only six defect classes:

```text
crazing
inclusion
patches
pitted_surface
rolled_in_scale
scratches
```

There is no:

```text
normal
unknown
unsupported
non-steel
```

class.

Therefore, an arbitrary input could still be assigned one of the six known defect classes.

Examples include:

```text
person
animal
car
building
food
general object
```

A separate supported-domain validator was introduced to reduce this problem.

# Input Preprocessing

Both supported and unsupported images were converted to:

```text
grayscale with 3 output channels
```

before training.

This was important because the NEU defect dataset is grayscale while many unsupported Caltech images contain color.

Without this step, the validator could learn the shortcut:

```text
grayscale → supported
color → unsupported
```

The common preprocessing pipeline was:

```text
Grayscale → 3 channels
Resize → 224 × 224
Tensor conversion
ImageNet normalization
```

# Real-World Steel Image Testing

After integration, additional steel images obtained from outside the original NEU dataset were tested.

Some of these real-world steel images produced supported-domain probabilities approximately in the range:

```text
0.60 – 0.80
```

These images were visually relevant steel surfaces but were rejected by the original:

```text
0.90
```

threshold.

This revealed an important practical domain-shift issue.

The validator was highly confident on NEU-like test images but less confident on steel images from different acquisition conditions.

Possible differences include:

- lighting
- camera distance
- cropping
- surface finish
- texture
- compression
- image source
- defect scale
- background
- contrast

---

# Final Deployment Threshold

The deployment threshold was therefore changed to:

```text
0.80
```

Final acceptance rule:

```text
supported_probability >= 0.80
```

Otherwise:

```text
analysis is stopped
```

---

# Threshold Selection Rationale

The final threshold of:

```text
0.80
```

was chosen because:

- it remained perfect on the constructed validation set
- it remained perfect on the constructed test set
- it rejected the known Caltech false accept with probability 0.773628
- it is less restrictive than 0.90
- it improves practical acceptance of real-world steel images
- it is still stricter than 0.70
- threshold 0.70 would reintroduce the known false acceptance

Therefore:

```text
0.80
```

provides a better balance between:

```text
rejecting unsupported images
```

and:

```text
accepting valid real-world steel images
```

for the current prototype.

---

# Threshold Limitation

The threshold:

```text
0.80
```

is not universal.

It depends on:

- training data
- supported-domain definition
- validator architecture
- preprocessing
- real-world image distribution

Future retraining with more varied real-world steel images may require recalibration.

---

# Final Robustness Rules

SteelVision now follows these rules:

```text
1. Validate the input domain first.

2. Reject unsupported inputs before defect analysis.

3. Use ResNet as the primary image-level classifier.

4. Use YOLO as supporting localization evidence.

5. Preserve secondary YOLO classes.

6. Do not hide ResNet–YOLO disagreement.

7. Treat YOLO no-detection as unavailable localization,
   not automatic classifier failure.

8. Use entropy as an uncertainty indicator.

9. Interpret Grad-CAM as model influence,
   not physical proof.

10. Keep the uploaded image authoritative.
```

# Main Findings

## Finding 1

ResNet-50 remains the strongest image-level classifier in the current SteelVision pipeline.

---

## Finding 2

Most ResNet–YOLO disagreement was caused by missing YOLO detections rather than contradictory classifications.

---

## Finding 3

When YOLO produced at least one detection, the ResNet-predicted class appeared somewhere among the detections in:

```text
100% of detected cases
```

on the evaluated test split.

---

## Finding 4

YOLO multi-class results should be preserved rather than reduced to only one class.

---

## Finding 5

A closed-set six-class classifier should not be exposed directly to arbitrary user images without a rejection mechanism.

---

## Finding 6

The MobileNetV3-Small validator strongly separated the constructed supported and unsupported datasets.

---

## Finding 7

The original 0.90 threshold was too strict for some real-world steel images outside the NEU acquisition distribution.

---

## Finding 8

A threshold of:

```text
0.80
```

provides a better practical balance while still achieving perfect performance on the constructed validation and test sets.

# Limitations

## Supported-Domain Coverage

The validator was trained mainly on:

```text
NEU steel defect images
Caltech-101
MVTec industrial hard negatives
```

Therefore, it may not generalize perfectly to all real-world steel images.

---

## Real-World Domain Shift

Steel images downloaded from other sources may differ substantially from NEU images.

Differences may include:

- lighting
- camera angle
- scale
- texture
- surface finish
- resolution
- compression
- background

This can reduce supported-domain probability even when the image is genuinely steel.

---

## Normal Steel Coverage

The six-class classifier does not contain a:

```text
normal
```

class.

Therefore, the current system is not a complete:

```text
normal steel vs defective steel
```

inspection system.

A future version should include representative defect-free steel images from the target acquisition domain.

---

## Unsupported Space Is Open-Ended

The unsupported-input space is effectively unlimited.

The validator cannot guarantee correct rejection of every possible out-of-distribution image.

---

## Threshold Generalization

The selected threshold:

```text
0.80
```

should be recalibrated if:

- the validator is retrained
- new steel data is added
- preprocessing changes
- new defect classes are introduced
- deployment conditions change

---

## Dataset Shortcut Risk

Converting all images to grayscale reduces one shortcut, but the validator may still learn dataset-specific patterns unrelated to true domain membership.

Future work should include more varied steel sources.

---

## Cross-Model Disagreement

ResNet and YOLO remain independent models.

Agreement does not guarantee correctness.

Disagreement does not automatically identify which model is correct.

---

## YOLO No-Detection Cases

YOLO may fail to localize a defect even when ResNet classifies the image correctly.

This was especially visible for:

```text
crazing
rolled_in_scale
```

Therefore:

```text
no detected bounding box
```

must not be interpreted as:

```text
no defect exists
```

---

## Grad-CAM

Grad-CAM visualizes model influence.

It does not provide:

- segmentation ground truth
- causal physical explanation
- engineering severity
- guaranteed defect boundaries

---

# Scientific Interpretation

After Phase 15, SteelVision can be described as:

> A multi-model steel surface defect analysis research system that validates whether an uploaded image sufficiently resembles its supported defect-analysis domain before performing image-level classification, uncertainty estimation, explainability, and spatial localization, while explicitly preserving cross-model disagreement.

It should not be described as:

```text
a universal steel inspection system
```

or:

```text
a perfect steel vs non-steel detector
```

or:

```text
a complete normal-vs-defective steel inspection system
```

because the current data does not support those claims.

# Conclusion

Phase 15 improved SteelVision from a closed-set application that always attempted defect classification into a more cautious and robust research system.

The major improvements were:

- ResNet–YOLO agreement was quantitatively evaluated
- model roles were clearly separated
- disagreements were preserved instead of hidden
- YOLO no-detection cases were interpreted correctly
- unsupported-input behavior was addressed
- a MobileNetV3-Small domain validator was trained
- industrial hard negatives were added
- probability distributions were analyzed
- threshold behavior was measured
- the initial 0.90 threshold was tested in real-world conditions
- the deployment threshold was adjusted to 0.80
- validation was enforced inside FastAPI
- Streamlit now stops downstream analysis for rejected inputs
- large datasets were excluded from Git while preparation scripts remained reproducible

The resulting system is more robust, interpretable, and scientifically responsible than the previous deployment pipeline.
